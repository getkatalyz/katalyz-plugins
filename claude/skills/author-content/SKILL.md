# Author dealroom or template content

Resolve the exact room with `katalyz:search_dealrooms` or template with `katalyz:search_dealroom_templates`. For a new target, follow the create-dealroom skill first and wait until creation is ready. Read `katalyz:get_canvas_authoring_guide`, `katalyz:get_content_overview`, and the relevant `katalyz:get_content_tree` before writing. Use the guide's examples and design families rather than inventing tree nodes, classes, or widget settings. Read `katalyz:get_content_design` before changing the target-wide palette, typography, header, navigation, or dealroom logo. Ask the seller to resolve ambiguous targets and clarify content they have not specified.

Create or edit pages with `katalyz:create_content_page` and `katalyz:update_content_page`. Create native widgets with `katalyz:create_content_widget`; page widgets return an unplaced `blockId` that must be placed with `katalyz:patch_content_tree` and `ATTACH_BLOCK_NODE`, while supported task-body widgets attach automatically. Use `katalyz:get_content_widget_options` for reference IDs and `katalyz:get_content_widgets` before `katalyz:update_content_widget`, especially for tables and question lists. Read `katalyz:get_content_tasks` before updating real action-plan tasks with `katalyz:update_content_task`; create missing ones with `katalyz:create_content_task` and attach root steps to an action-plan container. A timeline widget only displays tasks. Use `katalyz:update_content_design` for target-wide visual settings and `katalyz:rename_dealroom_template` for a template title. Confirm an exact page or widget before deleting it.

For a file or image in a page widget, find an existing durable resource with `katalyz:search_resources`, or use `katalyz:prepare_resource_upload` with `destination: "library"` and its companion completion tool after uploading the original bytes. Follow the existing create-dealroom skill's signed-URL handling: use the exact headers and byte size, send only to the returned first-party URL, keep the URL and token private, and complete only after a 2xx PUT. Temporary AI context resources cannot be attached to widgets. Read `katalyz:get_resource` before editing metadata with `katalyz:update_resource`; `katalyz:delete_resource` permanently removes a resource and its direct references across rooms and templates, so ask for explicit confirmation before calling it. An uncertain upload completion or deletion is not a reason to blindly retry.

Patch each page or task body with its current `contentTreeVersion` as `baseVersion` and stable node IDs. On a version conflict, read the tree again and recompute the patch; after a lost response, read it before considering a retry. Reuse an unplaced native widget found by `katalyz:get_content_widgets` instead of creating another. Inspect the saved receipt and reread content when normalization or generated IDs matter. Verify the page at its returned URL in an authenticated browser when available; otherwise give the seller the URL and say visual appearance was not checked. Request `katalyz:create_browser_login_link` only if the seller explicitly wants browser access and has granted its separate scope; its URL is a credential and opens a full application session beyond the connector's other scopes. Never put that URL in page content or share it.
